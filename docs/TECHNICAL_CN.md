# genodiff 技术说明文档

**零依赖、单二进制、FASTA 直入 VCF 输出的基因组比对与变异检测工具**

版本：v1.2 ｜ 语言：Rust（纯标准库，零第三方 crate）｜ 平台：Linux / Windows / macOS
测试：45 项单元与集成测试 ｜ 许可：MIT

---

## 一、开发原理

### 1.1 设计目标

genodiff 解决的核心问题是：**给定两个（或多个）已完成组装的单倍体基因组 FASTA，
直接产出一份标准化、可直接用于群体遗传学下游分析的变异位点 VCF 文件。**

这个需求长期被现有工具链忽视：读段比对软件（BWA、minimap2）面向"短读段 vs 参考"
设计，参数体系不适合"组装 vs 组装"；变异检测流程（GATK、DeepVariant）面向读段
数据；组装比较工具（MUMmer、SyRI、MUM&Co）输出自有中间格式，需要多步脚本转换才能
得到可用的 VCF。genodiff 从零开始为"组装对组装"这一场景构建整条流水线，
不复用任何读段比对的概念与参数。

### 1.2 核心设计理念：链（chain）是一等公民

传统流程把"比对"和"变异检测"分成两个世界：比对器输出逐碱基的 SAM/PAF，
变异检测器再从里面挖变异。genodiff 的核心观察是：**在组装间比较中，
一条共线性锚点链本身就是一个比对块，块的断点几何直接就是结构变异候选。**
链即比对、链即变异线索，两个阶段共享同一数据结构，不需要中间格式转换。

### 1.3 算法原理（八阶段流水线）

```
① 输入        参考基因组 FASTA + 查询基因组 FASTA（单倍体组装，条数不限）
② 索引        canonical minimizer（k=19, w=19），2-bit 打包 + 双向链滚动哈希，
               单一有序数组存储，约 24 字节/minimizer，支持磁盘持久化（.gdx）
③ 种子提取    查询 minimizer 经二分查找匹配参考，--max-occ 100 过滤高频重复种子
④ 贪心链式    漂移容忍 max(150, Δq/8)（上限 2000）+ patience(1000bp) 断链容忍，
               短链（<25 锚点或 <500bp 跨度）与次级链抑制
⑤ SV 推断     链断点几何 → DEL / INS / INV / DUP / BND 五类；
               倒位用对称间隙判据（query 侧与参考侧间隙等长即可桥接任意长度的
               共享重复侧翼）；重复吸引子过滤剔除旁系同源比对
⑥ 带状精比对  链内间隙做 Gotoh 三状态仿射间隙 DP
               （match +2 / mismatch −6 / gap open −8 / gap extend −2），
               带宽 = |m−n| + 24 + min(m,n)/6，与无带暴力实现逐对对拍验证
⑦ 变异提取    Mismatch 列 → SNP；Del/Ins 运行 → 锚定碱基形式 InDel；
               种子重叠滑移恢复同聚物 indel；全部左对齐规范化；
               反向链坐标镜像 + 碱基互补，等位基因统一到参考正链
⑧ 输出        VCF 4.2 → 多样本并集合并（GT 0/1）+ PAF 可视化
```

### 1.4 关键算法决策及依据

| 决策 | 理由 |
|---|---|
| minimizer 而非 full index | 800 Mb 基因组索引仅 ~19 GB 内存降到 24 B/minimizer 的有序数组，且 canonical 形式天然处理反向链 |
| 贪心链式 + patience 而非 DP 链式 | DP 链式 O(n²) 在百万锚点规模不可行；patience 机制让链穿越中频重复区。真实 800 Mb 数据上把无效断链从 1.03×10⁷ 降到 5.2×10⁵，入链锚点 +50% |
| 带状而非全局比对 | 链内间隙两侧长度差异受漂移参数约束，带宽公式保证最优路径不出带；与暴力实现逐对对拍验证等价 |
| SV 从链拓扑推断 | 断点精度受链端限制（数百 bp），但换来不依赖逐碱基比对即可检出大重排——两者互补 |
| 左对齐规范化 | 同聚物/重复区的 InDel 有多种等价表示，左对齐是 VCF 4.2 规范表示，保证不同样本的同一变异合并到同一行 |

## 二、运行机制

### 2.1 子命令体系

```
genodiff index   <ref.fa> <out.gdx>                     建参考索引（一次构建，反复使用）
genodiff map     <ref.gdx> <query.fa> > out.paf         链式比对 → PAF 共线性块
genodiff call    <ref.fa> <query.fa> -o out.vcf         全流程：FASTA 直入 VCF
genodiff sim     <ref.fa> <outdir>                      模拟突变基因组 + 真值 VCF
genodiff randref <out.fa> <length>                      随机参考生成（测试用）
```

`call` 是主入口：**一条命令内部完成索引构建 → 链式 → 精比对 → SV 推断 → VCF 写出**，
不需要用户编排任何中间步骤。

### 2.2 并行模型

- **contig 级并行**：查询基因组的每条 contig 是独立任务，工作线程通过共享任务队列
  动态领取；结果按原始顺序缓冲写出（乱序计算、有序输出）。
- **有界内存**：同时在途（in-flight）的 contig 序列总量受 4 GiB 预算约束，
  线程数再高峰值内存也可控。
- **零锁竞争**：参考索引构建后只读（Arc 共享），比对阶段无线程间写竞争。
- 实测：794 Mb × 794 Mb 基因组对，48 线程 call 全流程约 2 分钟，峰值内存约 4 GB。

### 2.3 批量机制（多样本）

`scripts/run_all.sh` 按 QUERIES 清单**逐个**基因组运行 call（串行，磁盘峰值
= 单个 VCF），完成后 `scripts/merge_vcfs.py` 把 N 个单样本 VCF 并集合并成
多样本矩阵：每个在任意样本中出现的变异位点一行，GT=1 携带 / GT=0 参考。
合并时 SV 的 INFO 注释（SVTYPE/END/SVLEN/CHR2/POS2）完整透传，信息无损。

### 2.4 SV 输出表示规范（v1.1 起，v1.2 增补 Q 坐标）

SV 的 ALT 表示按信息来源分两类，这是 genodiff 的一个重要设计：

| 类型 | 序列来源 | VCF 表示 |
|---|---|---|
| DEL / INV / DUP / BND | 参考基因组已知序列 | 符号记录 `<DEL>` 等 + `SVTYPE/END/SVLEN`（序列可按 POS+END 从参考还原，不写碱基） |
| INS | 查询特有（参考不存在） | ALT 携带实际插入碱基（≤ `--sv-seq-cap`，默认 100kb；超过转 `<INS>` + SVLEN） |

理由：把参考里本来就有的序列整段抄进 VCF 只会让文件膨胀几十倍而无信息增益；
只有"外来序列"不写就会丢失。该设计与 Sniffles/Manta 等主流 caller 的惯例一致，
同时 `SVTYPE/END/SVLEN` 保证类型与规模信息在合并、过滤、统计中始终可用。

**序列可追溯性**：头部 `##reference=file:...` 与 `##genodiff_query=file:...` 分别
记录参考与查询基因组的文件来源；INS/INV/DUP 记录的 INFO 额外携带
`QSEQ/QSTART/QEND`（该区段在查询基因组的 1-based 坐标），任何 SV 涉及的序列都
可通过 `samtools faidx` 按坐标直接提取，符号化表示不损失任何序列可达性。

### 2.5 正确性保障机制

- **内置模拟器**：`sim` 在参考上注入已知数量的 SNP/InDel/DEL/INS/INV/DUP，
  产出 query.fa + truth.vcf，构成自动化验证闭环；
- **对拍测试**：带状比对与无带暴力实现逐对对拍；minimizer 与暴力窗口扫描对拍；
- **规范化比较**：`scripts/compare_vcf_norm.py` 按左对齐规范化比较调用集与真值集；
- 45 项单元/集成测试覆盖每个算法阶段，`cargo test --release` 一键回归。

## 三、输入与输出文件

### 3.1 输入

| 文件 | 要求 |
|---|---|
| 参考基因组 FASTA | 单倍体组装，任意条数 contig；header 首个空白分隔词作为序列名 |
| 查询基因组 FASTA | 同上；contig 命名无需与参考对应；ref/query 角色可互换 |
| 碱基处理 | 大小写统一；N 与 IUPAC 简并碱基在变异位点跳过；兼容 Windows/Unix 换行 |

兼容性容错：header 尾随描述、空行、混合换行符均自动处理。

### 3.2 输出一：单样本 VCF 4.2（call）

标准 9 列 + 单样本 GT 列（单倍体，GT=1 携带变异）：

```
##fileformat=VCFv4.2
##contig=<ID=Chr1,length=102287719>
##ALT=<ID=DEL,Description="Deletion">          ← 5 类 SV 的符号等位基因声明
##INFO=<ID=SVTYPE,...>  ##INFO=<ID=END,...>  ##INFO=<ID=SVLEN,...>
#CHROM POS ID REF ALT QUAL FILTER INFO FORMAT sample
Chr1   26342 .  C   G    .    .      .    GT 1                          ← SNP
Chr1   26156 .  C   CTG  .    .      .    GT 1                          ← 2bp 插入
Chr1   123111 . GGCT...ACGA  G   .    .      .    GT 1                       ← 28bp 缺失
Chr1   73623 .  T   <DEL> .    .      SVTYPE=DEL;END=76888;SVLEN=3265   GT 1   ← 大缺失
Chr1   12527 .  C   CAATG...  .  .      SVTYPE=INS;SVLEN=210              GT 1   ← 插入(带序列)
Chr1   57026 .  A   <INV> .    .      SVTYPE=INV;END=65620;SVLEN=8595   GT 1   ← 倒位
Chr1   90391 .  T   <DUP> .    .      SVTYPE=DUP;END=94555;SVLEN=4164   GT 1   ← 重复
Chr1   700   .  A   <BND> .    .      SVTYPE=BND;CHR2=Chr2;POS2=300     GT 1   ← 易位
```

要点：
- 全部 InDel/INS 为**左对齐规范化**表示（同聚物表示唯一化）；
- 小 SV（≤ --sv-seq-cap 的 INS）携带碱基序列，参考来源 SV 用符号 + 坐标描述；
- INFO 字段标准自描述，可直接被 bcftools/vcftools 等下游工具读取。

### 3.3 输出二：PAF 共线性块（map）

```
q_name q_len q_start q_end strand r_name r_len r_start r_end n_anchors na:n_anchors
```

每行一条共线性锚点链（比对块），是三个可视化脚本的输入。

### 3.4 输出三：多样本合并 VCF

```
#CHROM POS ... FORMAT  Mca  Ms   Mf   ...
Chr1   26342 ... GT     1    0    1
Chr1   73623 ... GT     1    1    0
```

47.8M 位点 × 18 样本的真实数据矩阵可直接用于 PCA、系统发育、群体结构分析。

### 3.5 输出四：可视化

| 脚本 | 图型 |
|---|---|
| plot_syntenic_dotplot.py | 全基因组点阵图（蓝正向/红倒位） |
| plot_syntenic_linear.py | 全基因组线性双排图（ribbon 连接） |
| plot_syntenic_circos.py | 圈图 |
| plot_region_synteny.py | 区域片段级共线性（逐片段映射、倒位交叉、缺失空缺、易位候选，附文字报告） |

均支持 .png / .pdf / 混合 .svg（900dpi 底图 + 可编辑文本元素）。

## 四、当前同类软件的局限性

### 4.1 "比对器 + 变异检测器"拼装流程（minimap2 + SyRI 等）

1. **依赖地狱**：minimap2 + SyRI 需要同时安装 minimap2、Python3、NumPy、SciPy、
   Matplotlib、NetworkX、Pysam 等至少 4-7 个组件，版本兼容问题频发；
2. **中间格式膨胀**：SAM/PAF → 比对过滤 → SV 检测 → 格式转换，每步落盘，
   800 Mb 基因组对的中间文件可达数十 GB；
3. **参数体系错配**：minimap2 的默认参数为读段调优（-x asm5/asm10 虽有组装预设，
   但其链式与 gap 代价模型仍围绕读段误差模型设计）；
4. **输出非 VCF**：SyRI 输出自有 files（.out/.vandil 等），转标准 VCF 需另写脚本。

### 4.2 MUMmer 系（MUM&Co、nucmer-based 工具）

1. 依赖 MUMmer 3/4 + Python，MUMmer 在超大基因组上 delta 中间文件巨大且慢；
2. MUM&Co 输出部分 VCF 但 SV 分类不完整（缺独立 INV/DUP 分类）；
3. 基于最大唯一匹配（MUM），在重复丰富的植物基因组上锚点大量丢失。

### 4.3 共同的结构性问题

1. **共线性断裂**：通用比对器在中频重复区把共线链打断成碎片，下游 SV 检测
   面对的是残缺的块结构——这是植物基因组（重复占 80%+）假阴性的主要来源；
2. **无验证闭环**：用户无法方便地回答"这个工具在我的物种上准确率多少"；
3. **无多样本方案**：产出单比较结果后，合并到群体矩阵仍需 bcftools 等额外工具
   （且格式不兼容问题密集出现在这一步）；
4. **安装/部署成本高**：集群环境下多依赖安装往往比分析本身更耗时。

## 五、FASTA 直入 VCF 的创新性

### 5.1 一条命令替代一条工具链

```
传统:  minimap2 → sort/filter → syri → 手写脚本转 VCF → bcftools merge   (5+ 步, 4+ 依赖)
genodiff:  genodiff call ref.fa query.fa -o out.vcf                      (1 步, 0 依赖)
```

输入是组装 FASTA，输出是变异位点级 VCF——**跳过了 SAM/PAF/中间格式整个层次**。
这不是"封装了多步流程"，而是共线性链一等公民设计带来的结构简化：
链即比对块（PAF 输出可选），链断点即 SV 候选，链内间隙精比对即 SNP/InDel 来源，
三个层次共享同一份锚点数据。

### 5.2 直接产出可分析的变异位点矩阵

1. **位点级表示**：SNP/InDel/SV 统一为 VCF 位点行，左对齐规范化保证同位点
   跨样本可合并——直接得到可用于群体分析的 GT 矩阵，下游 PCA/系统发育/
   群体结构分析零转换对接；
2. **SV 表示规范化**（v1.1 起）：参考来源 SV 符号化（POS+END+SVLEN 完整描述），
   仅 INS 携带序列——文件体积可控（单基因组 VCF 94–283 MB，对比全序列写出的
   数十 GB），类型/规模信息在合并中无损；
3. **多样本合并内建**：merge 保留 SV INFO 注释，一个工具从 FASTA 走到群体矩阵；
4. **验证即工具**：模拟器 + 真值 VCF + 规范化比较脚本随软件发布，用户在自己的
   物种上 10 分钟内可复现精度评估。

### 5.3 针对真实基因组的算法创新

1. **patience 断链容忍**：链在中频重复区保持连续（真实数据无效断链 ↓95%）；
2. **对称间隙倒位判据**：桥接被任意长度共享重复侧翼分隔的倒位断点；
3. **种子重叠滑移 indel**：minimizer 采样间隔 ~10bp、长度 19bp，相邻种子重叠
   不等时隐藏的 indel 被精确恢复（长度精确、位置由左规范化钉住）；
4. **重复吸引子过滤**：16kb 参考 bin 被 ≥5 条互距 ≥50kb 的查询链命中即判为
   旁系同源堆积，整组剔除——真实数据 repeat-flagged 链 11,101 条/基因组，
   显著压制重复区假阳性；
5. **Junction 双侧间隙约束**：SV 判定要求链间隙在 query 侧与参考侧均 ≤100kb，
   错配链对产生的 Mb 级假 SV 从源头排除（真实数据最大 SVLEN=99,991，
   无一超限）。

### 5.4 精度与规模验证

| 验证 | 结果 |
|---|---|
| 模拟数据（5 Mb，5,530 注入变异） | SNP P=100% R=100%；InDel P=100% R=100%；四类 SV 100% 召回 |
| 单元/集成测试 | 45 项全过（含对拍测试、回归测试） |
| 真实数据（玉米属 794 Mb 参考 × 18 个近缘/单倍型基因组） | 批量 18/18 成功；单样本 VCF 94–283 MB；合并 47,780,455 位点 × 18 样本；单基因组 SNP≈5.5M、InDel≈2.4M、SV≈4.5 万条 |

## 六、Rust 实现与工程优势

### 6.1 零依赖

- **不使用任何第三方 crate**，仅 Rust 标准库——`cargo build` 不下载任何东西，
  离线环境可直接编译；没有 supply-chain 风险，没有版本漂移；
- 对比：同规模 C++ 工具链需要管理第三方库依赖，Python 工具依赖运行时环境。

### 6.2 单静态二进制

- 编译产物是一个自包含的可执行文件，`scp` 到服务器即可运行；
- 无解释器、无虚拟环境、无动态库依赖（Linux/Windows/macOS 原生支持）；
- 部署成本 = 一次 `cargo build --release`（约 15 秒），彻底消除
  "装环境两小时、跑分析两分钟"的行业常态。

### 6.3 性能

- **无 GC 的可预测内存**：索引为单一有序数组（~24 B/minimizer），比哈希表索引
  小一个量级；链状态 O(1)；800 Mb × 800 Mb 全流程 ~4 GB；
- **零拷贝流式设计**：FASTA 逐条读取，contig 处理完即释放；
- **数据并行**：contig 级多线程（std::thread + 共享队列），48 线程接近线性加速；
- 实测规模：794 Mb 基因组 call ≈ 2 分钟（48 线程）；18 基因组批量 33 分钟
  （12 线程 × 串行，磁盘峰值仅单个 VCF）。

### 6.4 内存安全与正确性

- Rust 所有权模型在**编译期**排除 use-after-free、数据竞争等内存错误——
  这类错误在 C/C++ 基因组工具中是长期存在的隐性正确性风险；
- 多线程部分无锁数据竞争（索引只读共享、结果通道传递），
  由编译器静态保证，而非依赖运行时纪律；
- 45 项测试（含对拍与端到端回归）+ 内置模拟验证闭环，构成可持续维护的质量基线。

### 6.5 可复现性

- 零依赖 + 静态二进制 + 确定性算法（无随机性，除 sim 的显式 seed），
  同输入跨平台产出一致结果，满足发表数据的可复现要求。

## 附：已知限制（如实声明）

1. SV 断点精度为链端级（~数百 bp），碱基级精化在路线图中；
2. 贪心链式在多拷贝区域可能选择次优拷贝（DP 链式在路线图中）；
3. 着丝粒/极端重复区在种子层不可比对——这是所有基于序列比对方法的共同边界；
4. 复杂重组（双侧间隙 >100kb 且无共享侧翼）报告为链断点，不做进一步分类。
